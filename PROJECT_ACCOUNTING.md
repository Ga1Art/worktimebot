# Учёт проектов и интеграция Yougile

Каждый проект в Yougile соответствует отдельной записи справочника бота. В проекте учитываются только монтажные часы и личные расходы сотрудников. Смены продолжают учитываться отдельно.

## Ввод данных

В Telegram и VK монтаж и расход требуют выбора активного проекта из справочника. Свободный ввод названия заменён выбором проекта, чтобы опечатки не разделяли часы одного проекта. Если проектов нет, администратор добавляет их вручную или запускает импорт.

Расход: дата → проект → описание → сумма → необязательный чек → подтверждение. Проект отображается в заявке администратора, личном списке расходов и уведомлении о решении. Одобренные, ожидающие и отклонённые расходы суммируются отдельно.

Для прошлого месяца проект также выбирается. Бот сохраняет заявку и отправляет администратору кнопки «Одобрить / Отклонить» в Telegram и VK. После одобрения запись автоматически попадает в PostgreSQL и архивный отчёт; монтажи и расходы сразу включаются в учёт проекта. Подробности — в [инструкции по заявкам](PAST_MONTH_REQUESTS.md).

## Настройка Yougile

1. Создайте API-ключ аккаунта с доступом к нужным проектам компании по [официальной документации](https://yougile.com/api/). Пароль аккаунта в боте не хранится.
2. Добавьте в серверный `.env`:

   ```dotenv
   YOUGILE_API_KEY=ваш-ключ
   YOUGILE_API_BASE_URL=https://yougile.com/api-v2
   YOUGILE_SYNC_INTERVAL_SECONDS=900
   ```

   Если компания использует другой домен или собственную установку, укажите её адрес API v2.
3. Перед обновлением работающей системы сохраните резервную копию базы и примените `migration_add_project_accounting.sql`. Это добавочная миграция, существующие данные сохраняются.
4. Перезапустите процессы с обновлённым кодом. Автоматический импорт выполняется в процессе `main.py`: при запуске и затем каждые 15 минут. При запуске только `vk_bot_start.py` используйте ручную команду или запустите процесс API.
5. Администратор может обновить справочник кнопкой «Обновить проекты Yougile» или командой `/sync_projects` в Telegram или VK. Также доступен `POST /projects-sync-yougile` с заголовком `X-API-Key`.

Интеграция только читает Yougile: часы, расходы и задачи туда не отправляются. Внутренний числовой ID бота сохраняется, ID Yougile хранится отдельно в `active_projects.yougile_id`. При первом импорте существующий ручной проект с точно совпадающим названием связывается с Yougile; проверьте названия перед подключением.

Переименование обновляет название проекта, сохраняя связи по ID. Удалённый в Yougile проект (`deleted=true`) становится неактивным в боте; записи сохраняются. Просто исчезнувший из ответа проект не деактивируется: причиной может быть изменение прав аккаунта. Завершение задач само по себе не закрывает проект. Локальное отключение импортированного проекта будет отменено следующей синхронизацией, если проект в Yougile остаётся активным.

Справочник бота требует уникальных названий: конфликт разных проектов с одинаковыми названиями отменяет всю синхронизацию. При сетевом сбое или неполном ответе база не обновляется. Выбор проектов продолжает работать из локальной базы.

## Отчёты и старые данные

Администратор видит суммарные монтажные часы и расходы по статусам в списке проектов. При очередной синхронизации Google Sheets лист `Projects` получает эти же показатели. Сам импорт из Yougile не запускает обновление Google Sheets.

`GET /projects/{внутренний_id}/report` с заголовком `X-API-Key` возвращает отчёт за всё время, включая неактивные проекты: ID Yougile, монтажные часы по сотрудникам, список расходов и суммы по статусам. Наличие чека отмечается полем `has_receipt`, содержимое чека через этот метод не выдаётся.

Миграция связывает старые монтажи только при однозначном совпадении названия. Несвязанные монтажи также учитываются по однозначно совпадающему названию в отчётах; неоднозначные записи требуют ручного назначения. Старые расходы остаются с `project_id=NULL` и отметкой «Проект не назначен»: администратор должен распределить их вручную после проверки. Новые расходы и монтажи без известного активного проекта не сохраняются.

Проверки без обращения к рабочим сервисам: `python -m unittest discover -s tests -v`.

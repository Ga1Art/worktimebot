# Инструкция для администратора

## Назначение системы
Система предназначена для учета:
- сотрудников;
- рабочих часов;
- расходов сотрудников на нужды компании;
- ставок;
- премий;
- штрафов;
- месячного отчета;
- публикации текущего и архивного отчета в Google Sheets.

Система состоит из:
- Telegram-бота;
- VK-бота;
- FastAPI API;
- PostgreSQL в Supabase;
- Google Sheets для рабочего и архивных листов.

## Что может администратор
Администратор может:
- подтверждать и отклонять заявки на регистрацию;
- подтверждать и отклонять расходы;
- смотреть активных пользователей и их ID;
- назначать ставки;
- назначать премии и штрафы;
- смотреть премии и штрафы сотрудников;
- объединять дубли сотрудников;
- закрывать месяц;
- получать `manager_table` через API;
- синхронизировать отчеты в Google Sheets;
- загружать ставки, премии и штрафы из служебных листов Google Sheets.

## Роли и доступ
Админские действия доступны:
- в Telegram;
- в VK, если сотрудник отмечен как администратор.

В Telegram админские действия работают:
- в админском чате;
- в личном чате с ботом, если пользователь является администратором.

## Интерфейс администратора
Основной сценарий работы теперь кнопочный.

В Telegram у администратора есть:
- `Админ-панель`;
- постраничные списки заявок и расходов;
- кнопки `Одобрить / Отклонить`;
- пошаговые формы для ставок, премий, штрафов, слияния дублей и закрытия месяца.

В VK доступен похожий сценарий:
- кнопки меню;
- кнопки для заявок и расходов;
- пошаговые формы для основных действий администратора.

Команды по-прежнему работают как резервный путь.

## Работа с регистрациями

### Как создается заявка
Заявка появляется, когда сотрудник:
- впервые запускает Telegram-бота;
- впервые запускает VK-бота и выбирает создание нового аккаунта.

В таблице `workers` создается запись со статусом:
- `registration_status = 'pending'`

### Просмотр заявок
Лучше использовать кнопки из админ-панели.

Резервные команды:
```text
/pending_users
```

### Подтверждение заявки
В интерфейсе:
- открыть список заявок;
- нажать `Одобрить`.

Резервная команда:
```text
/approve_user ID
```

Что происходит:
1. Сотрудник подтверждается.
2. Получает уведомление.
3. Получает доступ к рабочим функциям.

### Отклонение заявки
В интерфейсе:
- открыть список заявок;
- нажать `Отклонить`.

Резервная команда:
```text
/reject_user ID
```

Что происходит:
1. Заявка переводится в отклоненную.
2. Сотруднику уходит уведомление.

## Работа с расходами

### Что считается расходом
Расход — это трата сотрудника на нужды компании с последующей компенсацией.

Важно:
- расход не уменьшает выплату;
- расход прибавляется к выплате как компенсация;
- в отчеты попадает только после подтверждения.

### Статусы расходов
- `pending`
- `approved`
- `rejected`

### Просмотр расходов на проверку
Лучше использовать кнопки из админ-панели и постраничный список.

Резервная команда:
```text
/pending_expenses
```

### Подтверждение расхода
В интерфейсе:
- открыть список расходов;
- нажать `Одобрить`.

Резервная команда:
```text
/approve_expense ID
```

Что происходит:
1. Статус меняется на `approved`.
2. Сотруднику уходит уведомление.
3. Расход начинает учитываться в статистике, отчетах и `manager_table`.
4. Запускается фоновая автосинхронизация Google Sheets.

### Отклонение расхода
В интерфейсе:
- открыть список расходов;
- нажать `Отклонить`.

Резервная команда:
```text
/reject_expense ID
```

Что происходит:
1. Статус меняется на `rejected`.
2. Сотруднику уходит уведомление.
3. В выплату расход не попадает.

### Чеки
Если сотрудник приложил чек:
- файл сохраняется в `storage/receipts/`;
- в `expenses` записываются путь и метаданные;
- администратор получает заявку с информацией о наличии чека;
- при наличии доступного медиа чек может прийти вложением.

### Куда уходит уведомление по расходу
Уведомление о результате возвращается в тот же канал, где расход был создан:
- Telegram;
- VK.

## Работа со ставками
Ставки задаются отдельно для двух типов работ:
- `shift`
- `install`

### Просмотр ставок
Кнопочный сценарий:
- выбрать `Показать ставки`;
- выбрать сотрудника.

Команда:
```text
/rates WORKER_ID
```

### Установка ставки
Кнопочный сценарий:
1. Выбрать `Задать ставку`.
2. Выбрать сотрудника.
3. Выбрать тип работы.
4. Ввести ставку.
5. Подтвердить.

Команда:
```text
/set_rate WORKER_ID shift RATE
/set_rate WORKER_ID install RATE
```

Примеры:
```text
/set_rate 12 shift 500
/set_rate 12 install 700
```

Особенность расчета:
- в отчетах используется максимальная ставка сотрудника по каждому типу работ;
- это позволяет хранить историю изменений ставок.

После изменения ставки запускается фоновая синхронизация Google Sheets.

## Работа с премиями и штрафами

### Назначение премии
Кнопочный сценарий:
1. Выбрать `Назначить премию`.
2. Выбрать сотрудника.
3. Ввести сумму.
4. Ввести описание.
5. Подтвердить.

Команда:
```text
/add_bonus WORKER_ID AMOUNT DESCRIPTION
```

Пример:
```text
/add_bonus 12 5000 За отличную работу
```

Что происходит:
1. В `bonuses` добавляется запись с текущей датой.
2. Сотруднику уходит уведомление.
3. Запускается фоновая синхронизация Google Sheets.

### Назначение штрафа
Кнопочный сценарий аналогичный.

Команда:
```text
/add_penalty WORKER_ID AMOUNT DESCRIPTION
```

Пример:
```text
/add_penalty 12 1500 Опоздание на объект
```

Что происходит:
1. В `penalties` добавляется запись с текущей датой.
2. Сотруднику уходит уведомление.
3. Запускается фоновая синхронизация Google Sheets.

### Просмотр премий
```text
/bonuses WORKER_ID
```

Показываются премии сотрудника за текущий месяц.

### Просмотр штрафов
```text
/penalties WORKER_ID
```

Показываются штрафы сотрудника за текущий месяц.

## Список сотрудников и поиск ID
Основной способ быстро найти `WORKER_ID`:
```text
/users
```

Команда показывает:
- ID сотрудника;
- ФИО сотрудника.

Эти ID используются для ставок, премий, штрафов и объединения дублей.

## Объединение дублей сотрудников
Если один и тот же человек оказался создан в системе дважды, записи можно объединить.

Кнопочный сценарий:
1. Выбрать `Объединить дубли`.
2. Выбрать основную запись.
3. Выбрать запись-дубль.

Команда:
```text
/merge_workers KEEP_ID DUPLICATE_ID
```

Пример:
```text
/merge_workers 12 19
```

Что происходит:
- запись `KEEP_ID` остается основной;
- в нее переносятся `work_logs`, `expenses`, `bonuses`, `penalties`, `rates`;
- запись `DUPLICATE_ID` удаляется.

Ограничения:
- если конфликтуют разные `chat_id` или `vk_id`, операцию нужно выполнять внимательно;
- перед объединением лучше убедиться, что обе записи принадлежат одному человеку.

## Привязка второго мессенджера
Сотрудник получает код привязки через Telegram:
```text
/link_vk
```

После этого отправляет код в VK.

Для хранения таких кодов используется таблица `account_link_codes`.

## Закрытие месяца
Команда доступна в Telegram и VK:
```text
/close_month
/close_month MM.YYYY
/close_month YYYY-MM
```

Кнопочный сценарий тоже доступен: можно выбрать текущий месяц, предыдущий или ввести другой вручную.

Что делает закрытие месяца:
1. Формирует архивный отчет за выбранный месяц.
2. Пишет его на отдельный лист в Google Sheets с именем `YYYY-MM`.
3. Определяет следующий месяц.
4. Пересобирает текущий рабочий лист для следующего месяца.

## Google Sheets

### Основная логика
Google Sheets используется как внешний отчетный слой.

Отчет строится в Python и затем записывается в таблицу через `services/google_sheets.py`.

### Что попадает в отчет
Для каждого подтвержденного сотрудника:
- рабочие записи по дням;
- часы по сменам;
- часы по монтажам;
- подтвержденные расходы;
- премии;
- штрафы;
- итог к выплате.

### Важные правила расчета
- расходы прибавляются как компенсация;
- штрафы вычитаются;
- в отчет попадают только расходы со статусом `approved`;
- ставки берутся как `MAX(rate_per_hour)` по типу работ.

### Автосинхронизация
Фоновая синхронизация запускается после:
- добавления смены;
- добавления монтажа;
- подтверждения расхода;
- изменения ставки;
- добавления премии;
- добавления штрафа.

Синхронизация работает в режиме best-effort:
- если Google Sheets временно недоступен, основное действие не откатывается;
- ошибка фиксируется в логах.

### Служебные листы для админских данных
Поддерживаются отдельные листы:
- `Rates`
- `Bonuses`
- `Penalties`

Они могут использоваться как источник ставок, премий и штрафов через API синхронизации.

### API для Google Sheets
Доступны:
- `POST /admin-sheet-init` — создать служебные листы;
- `POST /admin-sheet-sync` — импортировать данные из служебных листов и обновить текущий отчетный лист.

## FastAPI API
Доступны основные endpoints:
- `GET /manager-table`
- `GET /monthly-report-preview`
- `POST /monthly-report-sync-current`
- `POST /monthly-report-archive`
- `POST /monthly-report-close`
- `POST /admin-sheet-init`
- `POST /admin-sheet-sync`

Все защищенные endpoints требуют `x_api_key`.

### SQL view `manager_table`
`manager_table` — представление для управленческой таблицы.

Текущая логика:
- берутся только подтвержденные сотрудники;
- учитывается только текущий месяц;
- расходы учитываются только если `status = 'approved'`;
- расходы прибавляются;
- штрафы вычитаются;
- `total_with_tax` считается как `total * 1.06`, то есть с компенсацией 6% налога самозанятому.

Важно:
- после изменения [manager_table.sql](/c:/Users/galee/worktimebot/manager_table.sql) нужно заново применить SQL в Supabase;
- простой рестарт контейнера view не обновляет.

## Уведомления

### Что получает сотрудник
Сотрудник может получать уведомления о:
- подтверждении регистрации;
- отклонении регистрации;
- подтверждении расхода;
- отклонении расхода;
- начисленной премии;
- назначенном штрафе.

### По какому каналу уходят уведомления
Для расходов уведомление возвращается в тот канал, где расход был создан:
- Telegram;
- VK.

Для регистраций, премий и штрафов уведомление уходит в привязанные контакты сотрудника.

## Рекомендуемый порядок работы администратора
1. Подтвердить новых сотрудников через список заявок.
2. Проверить и при необходимости настроить ставки.
3. Проверять расходы через список pending-расходов.
4. Назначать премии и штрафы при необходимости.
5. При обнаружении дублей объединять записи.
6. В конце месяца запускать закрытие месяца.

## Если цифры не сходятся
Проверьте по порядку:
- подтвержден ли сотрудник;
- подтвержден ли расход;
- указана ли ставка нужного типа работ;
- не создан ли дубль сотрудника;
- применен ли актуальный `manager_table.sql` в Supabase;
- отработала ли синхронизация Google Sheets без ошибок.

# Синхронизация админских данных из Google Sheets

## Назначение
Этот сценарий позволяет редактировать админские данные прямо в Google Sheets и подтягивать их в базу:
- ставки;
- премии;
- штрафы.

Синхронизация выполняется через API endpoint:
```text
POST /admin-sheet-sync
```

Для первичной инициализации листов есть отдельный endpoint:
```text
POST /admin-sheet-init
```

## Что сейчас синхронизируется

### Лист `Rates`
Используется для ставок сотрудников.

Структура:
```text
worker_id | full_name | shift_rate | install_rate
```

Особенности:
- в лист попадают все активные подтверждённые сотрудники;
- если ставка ещё не задана, бот проставляет `0`;
- `full_name` служебное поле для удобства, в БД по нему ничего не ищется;
- в БД сохраняются `shift_rate` и `install_rate`.

Пример:
```text
12 | Иван Иванов | 500 | 700
18 | Петр Петров | 550 | 0
```

### Основной текущий лист
В основном листе тоже есть колонки:
```text
worker_id | full_name | shift_rate | install_rate
```

Если администратор изменит ставки прямо там, они тоже будут подтянуты в БД при `admin-sheet-sync`.

### Лист `Bonuses`
Структура:
```text
worker_id | full_name | bonus_date | amount | description
```

Допустимые форматы даты:
- `YYYY-MM-DD`
- `DD.MM.YYYY`
- `DD/MM/YYYY`

### Лист `Penalties`
Структура:
```text
worker_id | full_name | penalty_date | amount | description
```

Допустимые форматы даты:
- `YYYY-MM-DD`
- `DD.MM.YYYY`
- `DD/MM/YYYY`

## Правила синхронизации ставок
- изменения ставок из `Rates` подтягиваются в БД;
- изменения ставок из основного текущего листа тоже подтягиваются в БД;
- если одну и ту же ставку меняли и в `Rates`, и в основном листе, приоритет у `Rates`;
- после синхронизации лист `Rates` перезаписывается из БД в нормализованном виде;
- после синхронизации текущий рабочий лист пересобирается заново.

## Инициализация листов
Один раз вызовите:
```text
POST /admin-sheet-init
```

Этот endpoint:
- создаст листы `Rates`, `Bonuses`, `Penalties`, если их ещё нет;
- заполнит `Rates` всеми активными сотрудниками;
- запишет заголовки колонок в `Bonuses` и `Penalties`.

## Ручная синхронизация
Если нужна ручная кнопка, используйте функцию:
```text
syncAdminData
```

Она отправляет `POST` в `/admin-sheet-sync`.

## Автосинхронизация после редактирования
Для этого используется installable `onEdit` trigger в Google Apps Script.

Он отслеживает изменения в листах:
- `Rates`
- `Bonuses`
- `Penalties`
- `current_month`

После редактирования ставится отложенная синхронизация с debounce примерно в `20` секунд, чтобы не дёргать API на каждую ячейку отдельно.

## Как подключить Apps Script
1. Откройте Google Sheets.
2. Перейдите в `Расширения -> Apps Script`.
3. Вставьте содержимое [google_apps_script/admin_sheet_sync.gs](C:/Users/galee/worktimebot/google_apps_script/admin_sheet_sync.gs).
4. Замените:
   - `https://YOUR_DOMAIN_OR_IP`
   - `YOUR_API_KEY`
5. Сохраните проект.

## Как включить автосинхронизацию
После вставки скрипта:
1. В редакторе Apps Script выберите функцию:
```text
installAutoSyncTrigger
```
2. Нажмите `Run`.
3. Подтвердите доступы Google.

После этого автосинхронизация будет включена.

## Как отключить автосинхронизацию
Запустите функцию:
```text
removeAutoSyncTriggers
```

## Полезные функции Apps Script
- `syncAdminData()` — ручная синхронизация
- `installAutoSyncTrigger()` — включить автосинхронизацию
- `removeAutoSyncTriggers()` — удалить триггеры
- `getLastAdminSyncAt()` — посмотреть время последней синхронизации

## Важные требования к данным
- `worker_id` должен существовать в базе;
- для ставок допустим `0` и положительные значения;
- `full_name` в листах `Rates`, `Bonuses`, `Penalties` нужен для удобства человека и в БД не используется как ключ;
- для премий и штрафов сумма должна быть больше `0`;
- описание обязательно для премий и штрафов;
- пустые строки игнорируются.

Если в данных есть ошибка, API вернёт сообщение с номером строки и причиной.

## Заголовок авторизации
Для вызова API используйте:
```text
x-api-key
```

Не `x_api_key`, а именно `x-api-key`.

## Что проверить, если не работает
- доступен ли ваш API снаружи;
- корректен ли `API_KEY`;
- созданы ли листы `Rates`, `Bonuses`, `Penalties`;
- есть ли у таблицы нужные колонки;
- нет ли неверных `worker_id` или дат;
- включён ли installable trigger через `installAutoSyncTrigger()`.
